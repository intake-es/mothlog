# Mothlog

> Receives the errors sent by Sentry SDKs, groups them into issues and lets you read, comment on and resolve them with a REST API and an MCP server. Everything requires `Authorization: Bearer <token>` except this file.

An agent can take an error from start to finish without leaving the MCP: find it, assign it to itself, read its context, fix it, comment and set the status. Every comment, assignment and status change is recorded in the issue's history with the token's name.

## MCP

- Server: {base}/mcp (Streamable HTTP, stateless; header `Authorization: Bearer <token>`)
- Flow: `list_issues` (with a search like `is:open is:unassigned environment:production`) → `assign_issue` with `"assignee": "me"` → `get_issue_context` → fix the code → `add_comment` → `set_issue_status` with `resolved_next` (resolved in the next release) or `resolved`.
- Tools: `list_issues`, `get_issue`, `get_issue_context`, `get_issue_tags`, `get_stacktrace`, `list_events`, `get_event`, `list_comments`, `add_comment`, `set_issue_status`, `assign_issue`, `list_assignees`, `list_releases`, `get_release`, `list_monitors`, `get_monitor` and `get_digest`.

## API

- [Context of an issue in Markdown]({base}/api/0/issues/{id}/context.md): summary, releases, environments, tags, the stack trace with code, breadcrumbs, history and what to do; `?environment=` and `?event=`.
- [Issues]({base}/api/0/issues/?query=is:open): the list, with the search language in `query`.
- [History]({base}/api/0/issues/{id}/history/): comments, status changes, assignments and Linear issues created by hand, by date.
- `POST {base}/api/0/issues/{id}/linear` creates the error's Linear issue and links it; if it already has one, it returns it without creating another.
- `POST {base}/api/0/issues/{id}/assignee` with `{"assignee": "me"}` (or a login or a token name) assigns; `DELETE` on the same path unassigns. [Who can be assigned]({base}/api/0/assignees/). In search, `assigned:me`, `is:assigned` and `is:unassigned`.
- `POST {base}/api/0/issues/{id}/comments/` with `{"body": "..."}` comments; `POST {base}/api/0/issues/{id}/status` with `{"status": "resolved_next", "comment": "..."}` changes the status.
- [Releases]({base}/api/0/releases/): releases with their deploys, what each one brought and their health: the share of crash-free sessions and users and the adoption.
- [Cron monitors]({base}/api/0/monitors/): crons with their latest status and the next expected run; `{base}/api/0/projects/{id}/monitors/{slug}/` gives the history of one.
- [Uptime monitors]({base}/api/0/uptime-monitors/): the URLs the service checks with their status and their 24 h and 30 day availability; `{base}/api/0/projects/{id}/uptime-monitors/{slug}/` gives their incidents and response times.
- [Project digest]({base}/api/0/projects/{id}/digest/preview): what's new, what came back, what's growing, crons, sites down and the health of the latest release over the last 24 hours (or 7 days), in `markdown`; in the MCP, `get_digest`.
